# 运动台数据分析工具：UI 测试逻辑准则与用例设计指南

> 本文档基于 MVP 四层架构与 UI 交互逻辑清单，为保障工业级数据分析工具的可靠性，提供核心的 UI 自测策略与测试用例设计准则。

---

## 维度一：架构隔离与数据流转准则 (Architecture & Data Flow)

**核心思想：验证 MVP 架构下“单向数据流”与“纯函数”的边界是否被严格遵守。**

1. **View 哑终端隔离测试**
   - 任何在 UI 上的操作（如点击按钮、编辑表格、移动鼠标），View 层仅允许更新自身内部的纯视觉状态（如切换布局 `LayoutChanged`）[cite: 2]。
   - 凡涉及数据计算或状态变更的，必须通过 `AppEventData` 包装后向外 `notify` 广播[cite: 3]。
   - **验证准则**：切断 Presenter 的监听，操作 UI 时，系统不应发生任何业务状态的改变，也不应出现未捕获的报错。

2. **Event Payload（事件载荷）完整性测试**
   - 针对所有广播事件（如 `ChannelCheckChanged`, `AxesClicked` 等），验证广播的 struct 数据（如 `{datasetIdx, colIdx, checked}`）是否完整且类型正确[cite: 2]。

3. **Model (SessionData) 的唯一事实来源 (Single Source of Truth) 测试**
   - View 层展示的所有数据（如通道名、Axes 映射关系、右 Y 轴列表）必须是 `SessionData` 状态的精确映射。
   - **验证准则**：通过命令行人为修改 `SessionData` 中的状态并调用 `Presenter.RefreshChannelTable` 或 `RenderAxes`，UI 必须能够完美同步[cite: 2]。

## 维度二：状态机与交互互斥准则 (State Machine & Mutex)

**核心思想：验证复杂的 UI 交互状态转移是否安全，是否存在非法的状态叠加。**

1. **上下文敏感 (Context-Aware) 鉴权准则**
   - 右键菜单必须基于选中的实体类型（父行数据集 vs. 子行通道）呈现不同的动作池[cite: 2]。
   - **验证准则**：数据集行（`isParent == true`）严禁触发通道级操作（如设为横轴、切片）；通道行严禁触发数据集级操作（如导出 Excel）[cite: 2]。

2. **逻辑互斥与防冲突准则**
   - **同一通道的状态互斥**：一个通道绝对不能同时被设为“横轴”和“右 Y 轴”[cite: 2]。
   - **视图防冲突**：如果某通道被设为“自定义横轴”，它在主渲染循环中必须被剔除（不参与左 Y 绘制），以防出现自身对自身的对角线绘制[cite: 2]。

3. **交互模式抢占准则 (Shift 拦截器 & Datatip)**
   - **行为分配**：拖拽 = 游标寻址 / 官方平移；`Shift` + 左键拖拽 = 官方选框放大；左键点击 = 打 Datatip 图钉[cite: 2, 3]。
   - **验证准则**：按下 `Shift` 键执行框选时，必须触发守卫逻辑拦截 `Datatip` 的生成，确保两者绝不发生状态干涉。

4. **生命周期协同准则 (Tab 与 Legend)**
   - 在隐藏页签内生成的 UI 组件往往尺寸为 0。
   - **验证准则**：切换 Tab 时，必须通过 `OnTabChanged` 设置 `PendingLegendRefresh_ = true`，并在随后的首次 `OnMouseMoved` 中延迟刷新 Legend，验证图例是否正确显示[cite: 2]。

5. **视图联动与隔离准则 (Axes Linkage Grouping)**
   - 坐标轴联动必须严格按照横轴引用分组，互不干扰[cite: 2]。
   - **验证准则**：当 Axes 1 和 Axes 2 设置了相同的自定义横轴，Axes 3 保持默认横轴时，滚动缩放 Axes 1 必须仅联动 Axes 2，Axes 3 的视图比例绝对不能受到影响[cite: 2]。

## 维度三：数据边界与动态渲染准则 (Data Boundaries & Rendering)

**核心思想：验证海量、极端、异构数据输入时的系统鲁棒性与视觉正确性。**

1. **尺寸与长度对齐准则 (Slice & Truncation)**
   - 多通道同时绘图时，各通道的数据长度可能不一致（尤其是使用了自定义切片 `ApplySlice` 或存在自定义横轴时）[cite: 2]。
   - **验证准则**：必须验证在渲染前通过 `min(length)` 进行安全的截断对齐[cite: 2]，保证 `plot(X, Y)` 时维度严格一致，不引发 MATLAB 报错。

2. **UI 容量边界准则**
   - **验证准则**：Axes 数量到达上限 6 个时，`+` 按钮失效或拦截；清空所有 Axes（0 个）后，再次点击通道勾选时，系统的回退逻辑必须正常（自动创建新 Axes 或提示错误）[cite: 2]。

3. **动态工程格式化准则 (Engineering Units)**
   - 游标读取到的 Y 值，必须基于其绝对值通过 `formatPrecisionValue` 进行判定[cite: 2]。
   - **验证准则**：输入边界值（如 `0.999 mm`, `1.000 mm`, `1e-6 mm`），验证其向 mm, um, nm, pm 的自动单位切换是否准确，且保留合理的小数位数[cite: 2]。

4. **格式免疫与降级准则 (Format Immunity)**
   - **验证准则**：强行导入非标准格式的 `.mat`（缺失 `sa_data_matrix` 等字段）或损坏的文件时，`DataReaderFactory` 必须抛出受控异常[cite: 3]。Presenter 捕获后需通过 View 弹出标准报错提示，内存中不应产生无效的 Dataset 对象[cite: 3]。

5. **图层属性恢复准则 (Right Y-axis Degradation)**
   - **验证准则**：为一个 Axes 设置多个右 Y 轴通道后，通过菜单执行“恢复默认 Y 轴”[cite: 2]。此时必须不仅删除右 Y 的虚线数据，还要验证坐标轴颜色、刻度、边框标签完全退化回单 Y 轴状态，无空刻度残留[cite: 2]。

6. **DPI 切换与 UI 锚点准则 (Display & Scaling)**
   - **验证准则**：在 150% 缩放的屏幕上启动软件并开启游标，随后拖拽至 100% 缩放的第二屏幕。验证 `uigridlayout` 布局不错乱[cite: 1]，且游标悬浮气泡 (`HoverText`) 的 1.5% 相对偏移量依然能防止遮挡波形与交点红圈[cite: 2]。

## 维度四：性能、并发与防伪死准则 (Performance & Concurrency)

**核心思想：防御 MATLAB 单线程模型下的事件泛滥与 UI 假死。**

1. **防重入与防抖准则 (Re-entrancy & Debouncing)**
   - 用户的高频操作（Event Flooding）不能击穿系统。
   - **验证准则**：在 `Rebuilding_` 或 `Highlighting_` 标志位为 `true` 的瞬间，模拟新的点击事件，验证事件是否被正确丢弃[cite: 3]。游标滑动必须存在 `idx == CursorLastIdx_` 的防抖拦截[cite: 2]。

2. **异步阻断与安全释放准则 (Fail-Safe UI)**
   - 执行大文件导入、FFT/PSD 计算、导出 Excel 等耗时操作时，必须唤起 `uiprogressdlg` 阻断界面[cite: 1, 2]。
   - **验证准则**：在 IO 读写期间强行注入异常，验证 `try...catch` 机制能否捕获异常，并且在 `finally` 中**必须**关闭加载动画，保证界面不会永久阻断假死[cite: 1]。

3. **内存溢出保护准则 (OOM Protection)**
   - **验证准则**：在可用物理内存极小的环境中导入超大体积数据集。当 MATLAB 底层抛出 `Out of memory` 异常时，Presenter 必须安全拦截，关闭阻断弹窗并给出 UI 提示，绝对禁止导致 MATLAB 进程崩溃闪退[cite: 1]。

4. **UI 刷新率保护准则**
   - **验证准则**：在使用 `uigridlayout` 动态增删坐标轴时，验证 `SettleUI()`（多次 `drawnow` 泵送）能否彻底消除惰性布局引发的错位残影[cite: 3]。

## 维度五：资源泄漏与生命周期准则 (Memory Leaks & Lifecycle)

**核心思想：杜绝 MATLAB 常见的句柄残留与僵尸窗口。**

1. **强弱引用与 Listener 回收准则**
   - **验证准则**：触发主窗口的 `CloseRequestFcn`，验证执行顺序必须是：销毁所有 Presenter -> 触发 Presenter 的 `delete` 析构函数 -> 清空 Listener 数组 -> 最后销毁 `uifigure`[cite: 2, 3]。操作后用 `memory` 指令观察无显著内存泄漏。

2. **游离弹窗管理准则 (Orphan Windows)**
   - 从主界面弹出的分析子窗口，必须登记在册。
   - **验证准则**：当关闭主窗口时，必须遍历 `PopupFigures` 跟踪列表并一并 `delete`[cite: 2]，绝对禁止出现“主程序已退出，分析子窗口依然残留在屏幕上”的情况。

3. **持久化回写准则 (Disk Synchronization)**
   - **验证准则**：使用右键进行“重命名数据集/通道”、“设置采样率”后，验证对应的 `.mat` 或 `.json` 文件被正确修改[cite: 2]。重启软件并重新加载该文件，验证修改依然存在。

## 附录：测试用例 (Test Case) 模板与示例

设计具体测试用例时，建议采用 **“【动作】+【状态组合】->【预期表现】”** 的格式，并映射到上述准则。

### 示例用例：TC-AXIS-004

*   **所属准则**：维度二 (逻辑互斥) & 维度三 (长度对齐)
*   **前置状态**：Axes 1 中已加载数据集 A 的通道 1 (1000个点) 和通道 2 (1000个点)。
*   **测试动作**：
    1. 右键通道 2 选择“设置切片范围”，截取前 500 个点[cite: 2]。
    2. 右键将通道 2 设为“横轴”[cite: 2]。
*   **预期表现**：
    1. 通道 2 不再作为波形显示。
    2. 横轴刻度数据变更为通道 2 的切片数据。
    3. 通道 1 的波形基于 `min(length)` 规则[cite: 2]，自动安全截断为 500 个点并正常显示，无数组维度不一致导致的报错。
